# AIA2ndBrain — Codebase Analysis Report

Repo: `/Users/carlitoswillis/workspace/AIA2ndBrain` (branch `main`, 5 commits, last: "update pdf extraction")

## 1. What the system does today, end-to-end

AIA2ndBrain is a ~160-line, single-process Node.js (ESM) daemon (`src/main.js`, run via `npm start`) that implements a "watch → classify → file" pipeline over an iCloud Drive vault:

1. **Startup / auto-heal**: `ensureStructure()` creates the PARA skeleton under the hardcoded vault path `~/Library/Mobile Documents/com~apple~CloudDocs/SecondBrain`: `Inbox/notes`, `Inbox/audio`, `Inbox/images`, `Projects`, `Areas`, `Resources`, `Archives`, `Reviews`. (Note: `Inbox/audio` and `Inbox/images` are created but nothing ever processes them — audio transcription is backlog only.)
2. **Watch**: `chokidar.watch(INBOX)` on `Inbox/notes` fires on every `add` event. Extension-based routing (lowercased): `.pdf` → PDF handler; `.txt`/`.md` → text handler; everything else logged as "Ignored".
3. **Extract**: PDFs are converted to text by shelling out to Poppler's `pdftotext -layout <file> -` via `execFile` (the `pdf-extract` npm dep is in package.json but is NOT used by the code — extraction is pure Poppler CLI). Text files are read with `fs.readFileSync(..., "utf8")`.
4. **Classify**: first 10,000 chars (`text.slice(0, 10000)`) are sent to Gemini (details in section 2), which returns `{area, domain, type, title, tags, summary}`.
5. **File**: `writeNoteAndMoveAsset()` slugifies the AI title (`[^a-z0-9]+` → `-`, fallback `"untitled"`), creates `VAULT/<area>/<slug>/`, writes `index.md` containing YAML frontmatter (`captured_at` ISO timestamp + all Gemini fields + `source_path`) followed by the 2–3 sentence summary as the body, then `fs.renameSync`s the original file into the same folder as `original.txt` or `asset.pdf`.

Important: **the full note text is NOT stored in `index.md`** — only the summary. The original content survives only as the moved asset file. There is no dedupe, no queue, no persistence of processing state, no retry, no UI, no tests.

`src/listModels.js` is a standalone utility that hits `GET https://generativelanguage.googleapis.com/v1/models?key=<GEMINI_API_KEY>` with raw `https` and prints available model names + supported generation methods — used to verify model availability (an active task in PROJECT_STATE.md).

## 2. How the Gemini classification works

- **SDK**: `@google/generative-ai` ^0.5.0 (the older Google SDK, not the newer `@google/genai`), client created from `process.env.GEMINI_API_KEY` via dotenv.
- **Model**: `models/gemini-2.5-pro`, called with `model.generateContent({contents: [{role: "user", parts: [{text: prompt}]}]})`. No `generationConfig`, no `responseMimeType: "application/json"`, no temperature, no system instruction, no JSON schema mode — structured output is enforced only by prompt text.
- **Prompt** (verbatim shape, single user turn, note text interpolated inline):
  ```
  Return STRICT JSON ONLY:
  {
    "area": "Projects|Areas|Resources|Archives",
    "domain": "Music|Career|Health|Finances|Creativity|Relationships|Other",
    "type": "idea|task|note|reflection|resource",
    "title": "short title <= 10 words",
    "tags": ["lowercase","keywords"],
    "summary": "2-3 sentence summary"
  }
  TEXT:
  ${text}
  ```
- **Response parsing**: raw text pulled from `result.response.candidates?.[0]?.content?.parts?.[0]?.text`, then a regex strips an optional ` ```json ... ``` ` fence, then `JSON.parse`. The parsed object is trusted as-is — no enum/schema validation of `area`/`domain`/`type`.
- **Fallback**: any error (API failure, quota, parse failure) is caught and returns a hardcoded default: `{area: "Resources", domain: "Other", type: "note", title: "Unclassified Capture", tags: [], summary: text.slice(0, 300)}` — so failures silently route to `Resources/unclassified-capture/`.

## 4. Notes/ directory — an Apple Notes export corpus (data, not runtime)

`Notes/` (git-ignored via an uncommitted `.gitignore` change; ~5,842 files) is a **historical Apple Notes export** (Exporter-style: `Failed Exports/`, `Icon` file, per-folder `images/` + `attachments/` subdirs), NOT the live vault the daemon watches. Layout:

```
Notes/
  Failed Exports/iCloud/{Archive/Daily Journal, Notes}/   <- ~notes with export-breaking names (colons etc.)
  iCloud/
    Archive/{Daily Journal (35 md), dreams (20), Gusto (53), Musica (127)}
    Projects/{autoJob (1), rumblr (1)}
    Resources/{songs (2), technical journal (2)}
    Notes/            <- the big unsorted bucket: 4,086 .md files
      images/  attachments/
```

File counts by type: 4,353 .md, ~1,100 images (png/jpg/jpeg/webp/heic/...), ~350 audio (mp3/m4a/wav/aif/amr/caf), 21 pdf, 7 MOV. Note format: filename is `DD-MM-YYYY-<title-fragment>.md` (dates span 2015–2026), content is an H1 title + plain markdown body — **no YAML frontmatter**. Inline images use relative links like `![UUID](images/UUID.png)`; attachments are UUID-named files. Some notes contain export artifacts (stray `</span>` fragments), checkbox lists (`- [ ]`), duplicates suffixed `-1`. So the Apple-Notes folder taxonomy already loosely mirrors PARA (Archive/Projects/Resources + an unsorted Notes bucket), which is presumably staged as backfill input for the pipeline.

## 6. What is reusable for a read-later app

- **The entire "classify → frontmatter → PARA folder" tail of the pipeline.** `classifyText()`, `writeNoteAndMoveAsset()`, and the slug/frontmatter conventions are content-source-agnostic — anything that produces a text blob (an article body, a highlight set, a transcript) can be dropped into it. A read-later app just needs to become another producer.
- **The Gemini plumbing**: working API-key setup, SDK call pattern, JSON-fence stripping, and a graceful degradation fallback. The prompt's enum design (`area/domain/type/tags/summary`) extends naturally with read-later fields (`source_url`, `author`, `reading_time`, `status: unread|read`, `kind: article|video|thread`).
- **The PARA vault contract**: iCloud path, folder-per-note with `index.md` + original asset, YAML frontmatter schema (`captured_at`, `area`, `domain`, `type`, `title`, `tags`, `source_path`). A read-later app writing this exact shape gets organization, iCloud sync, and future Obsidian/dashboard/embedding features "for free" as those land.
- **The Inbox drop-folder pattern as an integration API**: the cleanest coupling is file-based — the read-later app saves fetched article text as `.md`/`.txt` (or PDF) into `SecondBrain/Inbox/notes` and the existing watcher does the rest. Zero code changes needed for a v0 integration.
- **The `/ai` substrate pattern** (AGENTS/ARCHITECTURE/PROJECT_STATE + bundle script) is a copyable convention for the new repo.
- **The Notes corpus** is a realistic 4k-note test/backfill dataset for classification-quality and dedupe work, and its H1-plus-body format is the "legacy note" shape any importer must handle (no frontmatter, date-in-filename).

## 7. What is fragile (know before building on it)

1. **No write-completion debounce**: `chokidar.watch(INBOX)` has no `awaitWriteFinish` option, so a large file still syncing from iCloud (notoriously slow/partial) can be read half-written. iCloud placeholder files (`.icloud` stubs for non-downloaded files) are not handled at all.
2. **Silent misfiling on any Gemini failure**: the catch-all fallback files everything under `Resources/unclassified-capture/`; repeated failures collide on the same slug folder and the second `fs.renameSync` to `original.txt` overwrites the first — **data loss path**.
3. **Slug collisions generally**: two notes classified with the same title overwrite each other's `index.md` and asset (no uniqueness suffix, no existence check).
4. **No validation of Gemini output**: `meta.area` is used directly as a path segment; a hallucinated area creates arbitrary directories (`meta.area || "Resources"` only guards falsy, not wrong values). Prompt-injection via note content could steer routing.
5. **No idempotency/state**: chokidar `add` fires for pre-existing files on startup by default; a crash mid-processing leaves files in limbo; no processed-log, no dedupe against re-drops.
6. **`fs.renameSync` breaks across volumes** (EXDEV) if inbox and vault ever live on different filesystems.
7. **Original note text discarded from `index.md`** — only the summary is kept in Markdown; full-text search over the vault's md files won't find original content (it lives in `original.txt` next door).
8. **Hardcoded everything**: vault path, model name (`gemini-2.5-pro` — availability must be manually verified via `listModels.js`), 10k-char truncation (long PDFs classified on the first 10k chars only), domain enum.
9. **Dead/unused dep** (`pdf-extract`), SDK a major generation behind (`@google/generative-ai` 0.5.x vs current `@google/genai`), no structured-output mode so JSON parsing is regex-based.
10. **No tests, no CI, no logging beyond console**, single API key in `.env` with no rate-limit handling.
11. Doc drift risk: `CONTEXT_BUNDLE.md` is a snapshot (May 2026) and can go stale vs. code.

## 8. How a read-later app could feed this pipeline

- **Tier 0 (zero changes)**: read-later app fetches/cleans an article (readability extraction) and writes `<slug>.md` with the article text into `~/Library/Mobile Documents/com~apple~CloudDocs/SecondBrain/Inbox/notes`. Existing watcher classifies and files it. To preserve provenance, prepend a minimal header (URL, saved-at) into the text so Gemini sees it and it lands in `source_path`-adjacent metadata.
- **Tier 1 (small changes to main.js)**: (a) teach the pipeline to read incoming YAML frontmatter (it already imports `yaml`) so the read-later app can pass `source_url`, `saved_at`, `author` through to the output frontmatter instead of relying on Gemini; (b) extend the classification enum with read-later `type` values (`article`, `highlight`) and add `status: unread`; (c) keep full article text in `index.md` body under the summary so the vault is self-contained and searchable.
- **Tier 2 (shared library)**: extract `classifyText` + `writeNoteAndMoveAsset` + vault-path config into a shared module both the watcher and the read-later app import, so the read-later app can classify at save time (with URL/domain context Gemini can use) rather than round-tripping through the inbox.
- **Downstream synergy**: the existing backlog items (weekly digest, embeddings/vector search, Obsidian backlinks, dashboard) would automatically cover read-later content if it enters via this pipeline — the read-later app should therefore conform to the `index.md`+frontmatter contract rather than invent its own storage.
- **Fix first** before trusting it with a firehose of saved articles: awaitWriteFinish/iCloud-stub handling, slug-collision suffixing, Gemini output validation (enum-check `area`), and an idempotency ledger — items 1–5 in section 7.

Key file paths: `src/main.js` (entire pipeline), `src/listModels.js` (model check), `ai/PROJECT_STATE.md` (roadmap), `Notes/iCloud/Notes/` (4,086-note unsorted corpus), vault at `~/Library/Mobile Documents/com~apple~CloudDocs/SecondBrain`.

## Key takeaways
- The system is a single ~160-line Node daemon: chokidar watches iCloud SecondBrain/Inbox/notes, Gemini classifies .txt/.md/.pdf content, and each note becomes VAULT/<area>/<title-slug>/index.md (YAML frontmatter + 2-3 sentence summary) with the original file moved alongside as original.txt/asset.pdf.
- Gemini classification uses @google/generative-ai ^0.5.0 with models/gemini-2.5-pro and a prompt-only 'STRICT JSON' contract returning {area, domain, type, title, tags, summary}; parsing is regex code-fence stripping + JSON.parse with no schema validation and a silent fallback that misfiles failures into Resources/unclassified-capture.
- The cleanest read-later integration is file-based and needs zero code changes: save extracted article text as .md into Inbox/notes and the existing watcher classifies and files it into PARA automatically.
- Highly reusable pieces: the classify-then-write pipeline (classifyText + writeNoteAndMoveAsset), the frontmatter/vault contract (captured_at, area, domain, type, title, tags, source_path), the Gemini plumbing with fallback, and the /ai agent-docs substrate pattern.
- Major fragility to fix before feeding it volume: no awaitWriteFinish or iCloud .icloud-stub handling, slug collisions silently overwrite notes (data loss), unvalidated Gemini output used as filesystem paths, no idempotency/dedupe/state, and only the summary (not full text) is persisted in index.md.
- Notes/ is a git-ignored ~5,842-file Apple Notes export (4,353 .md, ~1,100 images, ~350 audio) whose format is H1 title + plain body with DD-MM-YYYY-title filenames and no frontmatter — a ready-made 4k-note backfill/test corpus, not the live vault.
- The Apple Notes export folders (Archive/Projects/Resources + a 4,086-note unsorted Notes bucket) already loosely mirror PARA, so backfill routing mostly means classifying the unsorted bucket.
- Config surface is minimal: one .env key (GEMINI_API_KEY), hardcoded vault path (~/Library/Mobile Documents/com~apple~CloudDocs/SecondBrain), hardcoded model name, 10k-char classification truncation, and an unused pdf-extract dependency (PDF text actually comes from Poppler pdftotext CLI).
- A read-later app should conform to the index.md+frontmatter vault contract (extending it with source_url, saved_at, status, article/highlight types) so backlog features — weekly digest, embeddings search, Obsidian backlinks, dashboard — cover saved articles for free.
- For deeper integration, extract classifyText/writeNoteAndMoveAsset into a shared module so the read-later app can classify at save time with URL context, and teach the watcher to pass through incoming YAML frontmatter (the yaml lib is already a dependency).
- Roadmap in ai/PROJECT_STATE.md already targets weekly digests, voice transcription, Obsidian backlinks, a React dashboard, and local vector search — a read-later feature slots in as another inbox producer rather than a parallel system.
